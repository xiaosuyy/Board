# Board 隐私与中国大陆可用性基线

> 本文件是**仓库级准入规范**：任何新功能在提交前都必须对照本文件自查。
> 文末附带当前代码的核查结论；结论只写**实际验证过**的东西，没验证的一律写「未验证」。

## 1. 中国大陆可用性

新增功能：

- 不得强依赖大陆无法正常访问的服务。
- 不得把境外服务作为唯一实现路径。
- 任何联网依赖必须**实际验证可访问性**（不能只凭“理论上应该能通”）。
- 如果功能需要第三方服务，应提供明确的服务依赖说明（见第 5 节）。

当前已知联网能力：

- **WebDAV / SyncClipboard 同步**：服务器地址由用户自己填写，不是固定后端；协议为 plain WebDAV。
  无境外强制依赖，大陆可用（用户自己的服务器可达即可）。
- **语音输入**：只调用系统 `SpeechRecognizer`，具体由设备上的识别服务提供方决定
  （可能是本地、也可能是厂商云服务）。Board 不绑定任何具体厂商、不内置任何境外 SDK。
- **翻译**：尚未实现（当前点击只提示未实现）。

## 2. 本地数据

语音：

- 不落盘
- 不入库
- 不写日志
- 不做历史
- 不做本地缓存

翻译：

- 不落盘
- 不入库
- 不写日志
- 不做历史
- 不做本地缓存

唯一允许持久化的语音相关数据，是**一个布尔值**：`voice_privacy_acknowledged`
（用户是否已确认过隐私说明）。它不包含任何语音内容、识别文本或识别历史。

## 3. 网络

- HTTPS 优先。
- 不允许无提示地使用 HTTP。
- 如果确实需要 HTTP，必须由用户明确开启并提示风险。
- 只发送完成当前操作所需的数据。
- 不上传与当前操作无关的信息（联系人、账号、剪贴板正文等）。

实现入口：`sync/webdav/WebDavUrlPolicy.kt`（发起请求前统一拦截）。

## 4. 日志

禁止打印：

- 原始语音
- 识别文本
- 翻译原文
- 翻译译文
- 密码
- Token
- Cookie
- Authorization
- 用户剪贴板正文

允许打印：长度、条数、类名、状态、版本号、错误类型等**不含内容**的信息。

## 5. 第三方服务

必须记录：

- 服务名称
- 使用原因
- 网络依赖
- 发送的数据
- 数据是否在本地保存
- 已知服务端留存政策

无法确认的事项必须标记：**「未确认」**。不得擅自写成「绝不留存」。

### 当前第三方依赖清单

| 服务 | 使用原因 | 网络依赖 | 发送的数据 | 本地保存 | 服务端留存政策 |
|---|---|---|---|---|---|
| 设备自带的语音识别服务（`RecognitionService`，具体提供方由设备决定） | 语音输入 | 未确认（可能本地、可能联网） | 由该服务自行决定；Board 只把音频交给系统 API | Board 不保存语音 / 识别文本 | **未确认**（Board 无法代第三方承诺） |
| 用户自建的 WebDAV 服务器 | 剪贴板 / 词库同步 | 用户填写的地址 | 仅同步负载（剪贴板条目、词库清单等用户勾选的内容） | 同步内容保存在用户自己的服务器上 | **未确认**（由用户自己的服务器决定） |
| 翻译服务（百度翻译通用文本翻译 API） | 翻译工具 | 是，**仅用户点击「翻译」时** | 待翻译文本 + 语言参数 + 用户自备的 APPID / 密钥 | Board 不保存原文、译文、历史、缓存 | **未确认**（以其服务协议与隐私政策为准） |

**Board 自身没有任何第三方 SDK**（无 Google Play Services / ML Kit / Firebase / 崩溃上报 SDK）。
`com.google.android.material` 只是本地 UI 组件库，不联网。

## 6. UI 披露

联网 / 第三方处理不能隐藏。涉及语音、翻译、AI、OCR、云同步时，必须让用户能够知道：

- 是否联网
- 发给谁
- 发什么

当前实现：

- **语音**：首次使用弹一次隐私说明（取消 / 继续），确认后才启动麦克风；
  语音面板底部常驻「系统语音识别 · 可能联网」，点它看完整说明。
  能可靠取到识别服务应用名时会显示「处理服务：XXX」，取不到就不显示（不猜）。
- **翻译**：面板顶栏常驻「<服务商> · 联网」，点它看完整隐私说明（联网、原文发给谁、
  Board 不保存、第三方留存以其政策为准）。未配置服务时明确提示「请先配置翻译服务」并提供入口。
- **同步**：设置页展示服务器地址与同步状态；明文 HTTP 需要用户显式开启并附风险提示。

| 语言：语音不落盘 / 不入库 / 不写日志 / 无历史 | 通过 | `voice/` 包内 grep `Log/File/Room/Dao/SharedPreferences` 为 0；识别文本只存在于内存，提交或返回即清空 |

## 附：B1 增量剪贴板历史（`/clipboard-log/`）隐私行为

> 如实记录 **B1（增量 Clipboard History v1）** 新增的数据行为，便于提交前复核。

### 远端

- 新增目录 **`/clipboard-log/<deviceId>.json`**（与 `/file/`、`/library/` **完全独立**）。
- 每台设备**只写自己的一份**；内容是该设备最近产生的 **Text** 事件。
- `≤256 KiB` 的 Text 以 **inline `text` 明文**存放在远端 JSON 中（与 `SyncClipboard.json` 的内联语义一致）；
  `>256 KiB` 的 Text **不产生事件**（不引用 `/file/`）。
- 该文件**会暂存近期文本明文**；保留上限 **200 条**。
- **compaction 在“本设备 publish 时”触发**，**不是严格每 7 天定时删除**；
  长期不再产生事件的设备，其 log 会停在 ≤200 条（有界，但不会自动按时间收缩）。
- 设备注册表复用 **`/library/devices.json`**（不新增第二套 registry）。

### 本地（Android / Windows）

- **不落任何 plaintext queue / outbox / 临时 txt**：待发正文只存在于**内存** pending 与 HTTP body。
- 本地新增的持久化**只有数字/metadata**：
  - `clipboard_log_seq`（Windows 为 `config.json` 的 `logSeq`）——本机 seq 水位；
  - `clipboard_log_last_seen_seq`——各远端设备的已消费水位（形如 `deviceId:seq`）。
- 日志只记录 `seq` / `bytes` / `count` / `status` / `minSeq` 等**不含正文**的字段。
- 远端历史事件到达后**只写入本地历史库，不写系统剪贴板**，因此不产生回环事件。
- `seq` 一旦分配只增不减；且**先落盘 seq 再做 PUT**，崩溃后不会重复分配已成功发布的 `seq`。

### 核查结论（B1）

| 项目 | 结论 | 依据 |
|---|---|---|
| 本地是否存在明文 outbox | 通过 | 真机 `files/` 与 `%APPDATA%` 下无 queue/txt/json outbox；待发正文仅在内存 |
| 远端是否暂存近期文本 | **是（如实披露）** | `/clipboard-log/<deviceId>.json` 含 ≤256 KiB inline Text |
| log 是否有界 | 通过 | `MAX_EVENTS = 200` |
| 是否严格 7 天定时删除 | **否** | compaction 由本设备 publish 触发 |
| 本地是否只存 metadata | 通过 | 仅 `logSeq` / `lastSeenSeq` |
| 远端 history 是否写回系统剪贴板 | 否 | 只入本地历史库（无回环） |
